01Quick start

Five steps, one of them a command.

You need Node.js 22 or newer with npm, and a Cloudflare account with access to Workers, D1 and R2. The steps target the published 0.1.0-rc.10 candidate.

  1. Generate and check a project locally

    This installs dependencies, builds the project and checks the deployment configuration. It creates no cloud resources.

  2. Sign in to Cloudflare and deploy

    Check that whoami shows the account you intend to use. Creation provisions a Worker, a D1 database and an R2 bucket in it. Add --domain site.example.com to bind a hostname you control from the first deployment.

    Already signed in and happy to do it in one go? npx mallok create my-site generates, verifies and deploys in a single command.

  3. Finish setup in the browser

    Open the setup URL the CLI prints and enter the one-time setup key. The wizard creates the administrator, sets the site name and languages, and offers example content — placeholders to replace before you present the site as your business.

  4. Bind a custom domain

    Edge caching needs a custom domain; a workers.dev address is for preview only. For edits to appear promptly, also add a cache-purge token (Zone → Cache Purge → Purge) and the zone id as Worker secrets. Without them, visitors see the previous version until the cache expires.

  5. Publish

    In the admin at /_mallok/app, edit a starter product or create your own, then publish. No rebuild. From a terminal or CI, publish a folder of bundles with a scoped API token instead:

Before you rely on it: this is a release candidate. There is no “Deploy to Cloudflare” button yet, and real inquiry email delivery has not been accepted end to end. Read the release status

npmjs.com/package/mallok

One command. Your account. Your content.

Mallok creates a Worker, a D1 database and an R2 bucket in your own Cloudflare account and deploys the site there. Nothing is hosted by Mallok, and there is no Mallok account to open.

npx mallok create my-site

Needs Node.js 22+ and wrangler login. Add --no-deploy to generate and check a project locally without creating cloud resources. Currently a 0.1 release candidate.
