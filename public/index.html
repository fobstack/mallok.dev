The Cloudflare-native CMS for multilingual B2B websites.

Mallok is an open-source alternative to WordPress and Ghost. Markdown content, a web admin, Liquid themes and inquiry forms — deployed into your own Cloudflare account, with no server to run and no rebuild when you publish.

Get started View the live demo
npx mallok create my-site

Needs Node.js 22+ and wrangler login. Creates resources in, and deploys to, your Cloudflare account.

  • Theme pages ship no client JS*
  • Multilingual + automatic hreflang
  • Starts on Cloudflare's free allowances (not unlimited)
  • Apache-2.0 open source

* Exceptions: the Turnstile script on the inquiry form and one declared carousel script on Atelier's homepage. Cloudflare features you enable may inject their own scripts.

01What is Mallok?

A CMS's editing, an edge network's delivery, and content you can take with you.

A traditional CMS gives you instant edits and charges you a server, a database and a stream of security updates. A static generator gives you fast pages and charges you a commit and a build for every typo. Mallok is built on three promises that refuse both prices.

01 / NO OPERATIONS

No server to run

There is no host to patch and no database server to keep alive. Mallok is one Worker in your own Cloudflare account. Mallok hosts nothing, cannot reach your site, and has no account system to sign up for.

What gets created
One Worker, one D1 database, one R2 bucket
02 / NO BUILD FOR CONTENT

Edits are live immediately

Saving is one D1 write plus a precise cache purge by tag. No CI run, no build queue, no redeploy. The same goes for settings, theme options and plugin settings.

What it needs
A custom domain and a cache-purge token. Without the token, visitors see the previous version until the cache expires.
03 / NO LOCK-IN

Your content leaves as Markdown

D1 stores standard Markdown with YAML front matter; media sits in R2. Export produces ordinary bundles — index.md plus images/ — designed to re-import into a fresh Mallok site byte-identically.

Also exportable
Inquiries, as CSV

02The boundary

Content needs no build. The frame does.

A site has two timelines, and Mallok keeps them visibly apart. Day-to-day work only touches the first; the second belongs to deployment, and the interface says so instead of pretending a theme switch is one click.

Live immediately

The content timeline

Changed in the admin or through the CLI by whoever runs the site day to day. No build, no deployment.

  1. save
  2. D1 write
  3. purge by tag
  4. live
  • Pages, articles, products, mediacontent
  • Site name, languages, navigation, SEO defaultssettings
  • The options a theme exposestheme options
  • Plugin on/off switch, settings and secretsplugin settings
Build + redeploy

The frame timeline

Changed in the source tree by someone technical. It travels with the code and takes effect on deployment — never as a one-click switch.

  1. edit source
  2. build
  3. deploy
  4. live
  • Switching or editing a themethemes
  • Installing or updating a pluginplugins
  • Moving to a new Mallok releasemallok upgrade
  • A theme switch migrates no content and changes no URLguarantee

03Multilingual

Multilingual is in the content model.

Every item has its own locale and belongs to a translation group. URLs are prefixed by language, and the sitemap carries hreflang without a plugin or a setting to remember.

Example site with two locales: en (default, no URL prefix) and zh-CN. x-default points at the default language.

One bundle is one translation group: index.md is the default locale, index.zh-CN.md the translation. With only one language, no hreflang is emitted. Sample content is illustrative; the company and product are fictional.

04The request path

Rendered once, then served from the edge.

Markdown is turned into a sanitised HTML fragment when you save. A visitor's first request applies the theme and stores the page in Cloudflare's cache; later requests never reach rendering. Open a node to see what it does and which free allowance it draws on.

SAVE

An edit

  1. Admin or CLIthe same management API
    The React admin is served as static files; the CLI publishes folders of Markdown through the same API.Static Assets: unlimited free requests
  2. Markdown → fragmentparsed and sanitised once
    Markdown becomes a sanitised HTML fragment when you save. The stored Markdown is never modified by sanitising.Workers free tier: 100k requests/day, 10 ms CPU each
  3. D1 writecontent + render_cache
    One write stores the Markdown and its fragment. The fragment table is derived data and can be rebuilt.D1 free tier: 5 GB, 5M rows read/day, 100k rows written/day
  4. Purge by taglive, with no build
    A precise cache purge by tag. It needs a custom domain and a cache-purge token; without the token, visitors see the previous version until the cache expires.Cache + Purge API: free; 5 tag purges per minute

  1. VisitorGET /zh-CN/products/…

06Release status

A release candidate, described honestly.

0.1.0-rc.10 is what npx mallok create installs today; rc.11 is on npm's next tag. Both are public release candidates, not the stable 0.1.

Release status and known limitations

Still open before a stable 0.1

  • Real inquiry email delivery through Turnstile and Resend has not been verified end to end.
  • Cold renders exceeded the 10 ms free-plan CPU target in 16 of 30 samples on rc.5. None failed; the limitation is known and accepted for the candidates.
  • A full export and restore into a second deployment, and a production upgrade and rollback, are still to be accepted.
  • There is no “Deploy to Cloudflare” button yet. The CLI is the way in.

07Quick start

One command. Your account. Your content.

Mallok creates a Worker, a D1 database and an R2 bucket in your own Cloudflare account and deploys the site there. Nothing is hosted by Mallok, and there is no Mallok account to open.

npx mallok create my-site

Needs Node.js 22+ and wrangler login. Add --no-deploy to generate and check a project locally without creating cloud resources. Currently a 0.1 release candidate.
