0.1 候选版 —— npm 上为 rc.10→

为多语言 B2B 网站而生的 Cloudflare 原生 CMS

Mallok 是开源的 WordPress / Ghost 替代方案：Markdown 内容、网页后台、Liquid 主题和询盘表单，一并部署到你自己的 Cloudflare 账号。不用维护服务器，发布内容也不用重新构建。

开始使用 查看在线演示
npx mallok create my-site

需要 Node.js 22 及以上，并先执行 wrangler login。会在你的 Cloudflare 账号里创建资源并完成部署。

  • 主题页面不带客户端 JS*
  • 多语言 + 自动 hreflang
  • 从 Cloudflare 免费额度起步（并非无限）
  • Apache-2.0 开源

* 例外：询盘表单的 Turnstile 脚本，以及 Atelier 首页声明的一个轮播脚本。你启用的 Cloudflare 功能可能会注入它们自己的脚本。

01Mallok 是什么

CMS 的编辑体验，边缘网络的交付速度，随时带得走的内容。

传统 CMS 改了就能上线，代价是一台服务器、一个数据库和没完没了的安全更新。静态生成器页面够快，代价是改个错别字也要提交、构建、再部署。Mallok 的三个承诺，就是这两种代价都不付。

01 / 免运维

不用维护服务器

没有要打补丁的主机，也没有要守着的数据库服务器。Mallok 就是你自己 Cloudflare 账号里的一个 Worker。Mallok 不托管任何东西，接触不到你的网站，也没有需要注册的账号体系。

会创建什么
一个 Worker、一个 D1 数据库、一个 R2 存储桶
02 / 内容免构建

改完立即生效

保存就是一次 D1 写入，加一次按标签的精确缓存清除。没有 CI，没有构建队列，也不用重新部署。站点设置、主题选项和插件设置同样如此。

前提条件
一个自定义域名和一个清缓存令牌。没有令牌时，访客要等缓存过期才能看到新内容。
03 / 不锁定

内容以 Markdown 带走

D1 里存的是带 YAML front matter 的标准 Markdown，媒体放在 R2。导出得到普通的内容包——index.md 加 images/——设计目标是能逐字节一致地重新导入另一个全新的 Mallok 站点。

同样可以导出
询盘记录，CSV 格式

02边界

内容不需要构建，框架需要。

一个网站有两条时间线，Mallok 把它们分得清清楚楚。日常运营只碰第一条；第二条属于部署，界面会如实说明，而不是把换主题包装成一键操作。

立即生效

内容时间线

由日常运营网站的人在后台或通过 CLI 修改。不需要构建，也不需要部署。

  1. 保存
  2. 写入 D1
  3. 按标签清缓存
  4. 上线
  • 页面、文章、产品、媒体内容
  • 站点名称、语言、导航、SEO 默认值设置
  • 主题开放的选项主题选项
  • 插件的启用开关、设置与密钥插件设置
构建并重新部署

框架时间线

由技术人员在源码里修改，随代码一起发布，部署后才生效——不会伪装成一键切换。

  1. 改源码
  2. 构建
  3. 部署
  4. 上线
  • 切换或修改主题主题
  • 安装或更新插件插件
  • 升级 Mallok 版本mallok upgrade
  • 切换主题不迁移内容，也不改变任何 URL保证

03多语言

多语言是内容模型的一部分。

每条内容都有自己的语言，并归属一个翻译组。URL 按语言加前缀，sitemap 自动带上 hreflang，不需要插件，也没有容易忘的开关。

示例站点有两种语言：en（默认语言，URL 不加前缀）和 zh-CN。x-default 指向默认语言。

一个内容包就是一个翻译组：index.md 是默认语言，index.zh-CN.md 是译文。只有一种语言时不会输出 hreflang。 示例内容仅作演示，企业与产品均为虚构。

04请求路径

渲染一次，之后由边缘直接返回。

保存时，Markdown 就被转成净化过的 HTML 片段。访客的第一次请求套上主题，并把页面写进 Cloudflare 缓存；之后的请求根本不会走到渲染。点开节点，可以看到它做什么、用的是哪一项免费额度。

SAVE

一次编辑

  1. 后台或 CLI同一套管理 API
    React 后台以静态文件提供；CLI 通过同一套 API 发布 Markdown 目录。Static Assets：请求免费且不限量
  2. Markdown → 片段解析并净化一次
    保存时，Markdown 被转成净化过的 HTML 片段。净化不会改动存储的 Markdown 原文。Workers 免费额度：每天 10 万次请求，每次 10 ms CPU
  3. 写入 D1content + render_cache
    一次写入同时保存 Markdown 和它的片段。片段表是派生数据，可以重建。D1 免费额度：5 GB，每天读 500 万行、写 10 万行
  4. 按标签清除缓存上线，不需要构建
    按标签精确清除缓存。需要自定义域名和清缓存令牌；没有令牌时，访客要等缓存过期才能看到新内容。Cache 与 Purge API：免费；按标签清除每分钟 5 次

解析只在保存时做一次。

HIT

绝大多数访客请求

  1. 访客GET /zh-CN/products/…
  2. 边缘缓存cache.match() → HIT
  3. 直接返回缓存页面页面代码还没开始运行
    缓存页面在任何页面代码运行之前就被返回：不渲染；Worker 已启动时也不读数据库。新启动的 Worker 处理的第一个请求还会对 D1 做一次启动检查。rc.5 一次部署的 30 次确认命中里，CPU 实测为 0–1 ms；这组样本不能代表之后的候选版。

不渲染；Worker 已启动时也不读数据库。

MISS

冷渲染

  1. 访客GET
  2. 边缘缓存MISS
  3. Worker 读取 D1最多 4 次往返
    设置、内容及其片段、导航——无论站点有多少内容。这一步不解析 Markdown。D1 免费额度：5 GB，每天读 500 万行、写 10 万行
  4. Liquid 主题片段 → 完整页面
    主题把片段套成完整页面。模板随 Worker 一起打包。Workers 免费额度：每天 10 万次请求，每次 10 ms CPU
  5. cache.put()Cache-Tag: site, c:<id>, …
    页面带着标签写进 Cloudflare 缓存，之后的保存就能只清除它改动过的页面。

无论站点有多少内容，最多 4 次 D1 往返。这一步不解析 Markdown。

MEDIA

图片与文件

  1. 访客GET 图片
  2. R2直接提供
    媒体由 R2 自定义域名直接提供；没有配置时走 /media/* 代理。R2 免费额度：每月 10 GB，出口流量免费

图片在上传时由浏览器转成 WebP，并生成多种宽度。

免费额度依据 Cloudflare 官方文档，核对于 2026-08-28，之后可能有变化；它们是额度，不是无限使用的承诺。 成本阶梯

05主题

内置五套主题，共用一个内容模型。

主题是项目源码里的声明式 Liquid 模板。更换主题需要重新部署——但不会动任何内容，也不会改任何 URL。

06发布状态

这是候选版，我们如实说明。

目前 npx mallok create 安装的是 0.1.0-rc.10；rc.11 在 npm 的 next 标签下。两者都是公开候选版，不是 0.1 稳定版。

发布状态与已知限制

稳定版 0.1 之前仍未完成的事

  • 通过 Turnstile 和 Resend 的真实询盘邮件送达，尚未完成端到端验证。
  • rc.5 的 30 次冷渲染样本中有 16 次超过免费套餐 10 ms 的 CPU 目标。没有请求失败；这是候选版已知并接受的限制。
  • 完整导出并恢复到第二个部署，以及生产环境的升级与回滚，仍待验收。
  • 目前还没有“Deploy to Cloudflare”按钮，入口是 CLI。

07快速开始

一条命令，部署到你自己的账号。

Mallok 会在你自己的 Cloudflare 账号里创建 Worker、D1 数据库和 R2 存储桶，并把网站部署上去。Mallok 不托管任何东西，也不需要注册 Mallok 账号。

npx mallok create my-site

需要 Node.js 22 及以上，并先执行 wrangler login。加上 --no-deploy 只在本地生成并检查项目，不创建云资源。当前为 0.1 候选版。
